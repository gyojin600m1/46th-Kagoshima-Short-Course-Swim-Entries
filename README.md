`index.html` 1ファイルだけで動く（外部通信は閲覧カウンターのみ。`file://` でもGitHub Pagesでもそのまま動く）。

## できること

- **選手** … 名前・ひらがな・チーム名で検索。カードに「⏰ 11:21・12:16」のように泳ぐ時刻の目安、開くと種目ごとに予想の組・レーン。
- **種目** … 種目ごとの出場者をエントリータイム順に。各行に時刻の目安と組。
- **日程** … 競技順序・開始予定時刻・公式の組数・休憩。
- **リレー** … 申込チーム。
- **組・レーン** … エントリータイムからの予想（8レーン・全年齢区分まとめてタイム順、第1組＝最も遅い組）。組ごとに時刻の目安。
- **当日プラン** … 選手を選ぶと、レースの時刻から招集（10分前）・食事の目安・準備・ダウンを逆算して1日ぶん並べる。
  「親子の水泳大会 1日ナビ」（[swim-family-day-navi](https://gyojin600m1.github.io/swim-family-day-navi/)）の機能を組み込んだもの：
  - 一番上に「次の予定」と「済みました」、各行にチェック
  - 「＋ 兄弟・姉妹」で最大4人を1つの予定表に（出番が20分以内に重なると注意を出す）
  - 起床・会場到着・朝食・コーチの集合時刻・追加の予定・メモを入力（時刻に反映）
  - 補食の候補に食品（10種類）を選べる。持ち物チェック・親子でできる準備・食事と水分の考え方・次の大会へのメモ
  - 予定のコピー・印刷
  - 食事の目安は1日ナビのルール：朝食は準備の約2時間前、補食は出番の約1時間前（直前に食べていなければ・1回まで）、昼食は次の集合まで約2時間あくところ
  - 入力・チェックはこの端末（localStorage）だけに保存。外部には送らない
- **大会情報** … 日程・当日の手続き・年齢区分。

## 当日の速報（自動）

- `.github/workflows/live-results.yml` が大会当日（11/1）、日水連 Live Results を40秒おきに見て、
  結果が増えたら `index.html` と `live.json` を更新して `main` と `gh-pages` に push する。
  1回の実行を最長5時間50分にして、終わるときに次の実行を自分で予約してつなぐ（cron は再始動用）。
- 取り込みは `tools/live_results.py`。大会は当日に Live Results の大会一覧から自動で探す（鹿児島・11/1・短水路）。
  - 組・レーンは公式プログラムのまま（速報側のレーン番号はプールによってずれるので照合だけに使う）
  - 申込と突き合わない行が2割を超えたら書き込まない（別の大会を拾ったときに間違いを出さない）
  - Live Results の大会お知らせに転載の掲示が出たら止まる
  - 順位は競技No.の全組が終わってから、全区分まとめたタイム順（失格・棄権には付けない）
  - 結果が入るとヘッダーに「速報中」、上に公式速報（Live Results）へのボタン、見ている画面には「新しい結果があります」
- 手で動かす：Actions → 「速報を自動で取り込む」→ Run workflow（空欄＝大会終了まで／1＝1回だけ／「動作確認だけ」＝公開ページに届くかの確認）
- 止める：実行中のものを Cancel し、この workflow を Disable workflow

## 時刻の目安の出し方

二次要項に載るのは種目ごとの開始時刻だけ。種目の持ち時間（次の種目の開始まで。休憩は除く）を、
各組の「いちばん遅いエントリータイム＋入れ替えの時間」で割り振って、組ごとの泳ぎ出しを出している
（入れ替えの時間＝（持ち時間 − 各組の最遅タイムの合計）÷ 組数。二次要項の時刻表もほぼこの作り）。
組・レーンは公式プログラムどおりだが、組ごとの時刻は計算なので目安。招集に遅れないよう分は切り捨て。

データは `index.html` の `const DATA = /*__DATA__*/{…}` の1行（`program[].startTime / endTime / heats / breakAfter`、`meta.dayPlan` など）。
